# 非目标（v1 明确不做的事）

与 Avalon 插件体系的 NON-GOALS 对齐，记录 v1 的边界，避免把 backlog
误读成缺陷。每一项都是**决定**，不是遗漏。

1. **不做热加载**：`Plugins.json` 改动需重启 Cascade 生效。插件进程
   本身随时可独立启停/替换（连接级失败会自动重协商），但清单拓扑
   （增删插件、改密钥）不经重启不生效。
2. **不做插件→Cascade 调用**：v1 只有 Cascade→插件一个方向。插件
   不能主动给 Cascade 下指令（例如主动发起跳转）；需要该能力时另行
   设计鉴权面，不隐式开放。
3. **不做 deliver 档（WAL 至少一次）**：Cascade 当前没有必须 surviving
   插件宕机的事件（对局结算发生在后端侧，由 Avalon 的 game.over 承载）。
   观察档失败即弃是**语义**不是缺陷；未来出现必须不丢的事件时按
   Avalon `outbox.go` 同形增加，不改造现有两档。
4. **~~不做 HTTP 状态端点~~（已撤销该决定）**：契约库已把
   `GET /api/plugins` 登记为接口面的一部分（`cascade-proxy.yaml`），
   长期挂"计划端点"豁免等于没有防线；该端点已实现——返回
   `{"plugins": [PluginStatus...]}`，字段名与契约锁定的 camelCase 一致，
   字段级对齐测试见 `internal/plugin/hub_test.go::TestPluginStatusJSONContract`。
5. **不做插件分发/市场**：插件由运营自行部署（二进制/容器皆可）。
   竞品调查的教训：分发绑死单点域名会生态清零；将来若做，必须内容
   寻址（如 GitHub Releases），且与宿主版本以 manifest 协商闸门解耦。
6. **不由 Cascade 拉起插件进程**：插件生命周期归运营/部署系统（本机栈
   由 `stack/up.sh` 管理）。Cascade 只负责调用、协商与失败隔离。
7. **不加载第三方代码进进程**：扩展面只有进程外 HTTP。任何"进程内
   插件/脚本引擎"提案都与本条冲突，需要先推翻本条（见竞品调查结论：
   进程内零隔离是共性败因）。
8. **不做多版本并行协商**：每个事件 v1 只有版本 1。版本交集机制已就位
   （manifest `versions`），但宿主暂不发送 >1 的版本。
