# 失败模式（cascade-plugin/v1）

总原则：**插件的任何失败都不得阻塞玩家链路**。观察档尽力投递；否决档
除"有效否决"外一律 fail-open 放行。

## 宿主侧（Cascade）

| 失败 | 行为 |
|---|---|
| 清单缺失/为空 | 零插件、零网络 I/O，行为与未启用逐字节一致 |
| 清单非法（版本/重名/非法 URL/密钥短/未知否决事件） | 启动显式失败，不静默降级 |
| 启动时插件不可达 | 记日志，后台退避重协商（5s→5min），不阻塞启动 |
| 观察档投递失败（非 2xx/超时/验签失败） | 丢弃该条 + 计数 `dropped`，不重试 |
| 观察档连接级失败（拒连/进程死） | 标记 unready → 重协商；期间事件继续入队（积压） |
| 队列满 | 丢最旧 + 计数 + WARN |
| 否决档：超时/不可达/非 2xx/应答未签名/验签失败/JSON 非法/缺 `allowed`/否决无理由 | **fail-open 放行** + 计数 `fail_open` + WARN |
| 否决档：授权插件未就绪 | 跳过咨询，计 `fail_open`（它本应参与） |
| 否决档：有效否决 | 取消转向；玩家收到本地化消息（含净化后的理由）；计数 `denied` |
| worker panic | recover + ERROR 日志；其余插件不受影响 |

## 插件侧义务

| 场景 | 义务 |
|---|---|
| 验签失败 | 回 401，不处理 |
| 未订阅的事件到达 | 回 404（配置漂移信号） |
| 载荷非法 | 回非 2xx（观察档会被丢弃计数）；若只想跳过，回 200 |
| 否决但无理由 | 会被宿主当畸形应答 fail-open —— 否决必须给可读理由 |
| 重复投递 | 观察档不保证不重不漏，插件按需以 `eventId` 去重 |

## 计数器

每插件维护 `delivered / dropped / denied / fail_open / queued`，
启动日志打印 ready 行，关闭时打印 shutdown summary；状态快照由
`Hub.Status()` 提供（HTTP 状态端点待契约登记后开放，见 knowledge/0008）。
